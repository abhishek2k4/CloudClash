# Implemented Features and Current Scope

This document is a snapshot of behavior present in the repository. Re-check code before describing any capability as complete.

## 1. Product scope

CloudClash is a web-only, real-time quiz application designed for a host-led event in one active room. The current server supports one active competition at a time.

## 2. Accounts and profiles

- Email/password sign-up and sign-in through Supabase Auth.
- Email confirmation can be required by Supabase project settings.
- Saved player game name and bio are stored in Supabase Auth user metadata.
- Signed-in users can host quizzes and can also join as participants.
- Guests can join a room without creating an account.
- A saved game name can prefill the participant join form.

## 3. Host quiz setup

- Signed-in host creates a room with a name and configurable round count (server validation currently allows 1–10).
- Questions can be created manually or imported by CSV.
- Manual authoring supports editing, duplication, deletion, reordering, four options, correct option, explanation and round assignment.
- CSV template/import supports the documented columns and validates required values.
- Round-specific CSV upload behavior exists in the backend; use the current dashboard template rather than assuming one universal CSV schema for every upload path.
- Quiz settings include per-round question duration and marks, speed bonus percentage, and optional elimination/advance counts.

## 4. Live gameplay

- Room code is generated by the backend and used by participants to join.
- One answer per participant per question is enforced server-side.
- Timed questions progress automatically.
- Host can pause/resume an open question and end/control the quiz lifecycle.
- Correct answer and explanation are revealed after the question has ended, not in the initial participant question payload.
- Round breaks provide a standings and optional elimination review step. The host can end the quiz early from a round break, just as during an active/paused round; early endings use the normal final-results and archive flow.
- After a quiz ends, the host can start another quiz without leaving the host area. The next room starts with a clean question bank and fresh setup state.
- Eliminated participants may remain connected as spectators; server-side answer acceptance must reject them.
- The leaderboard is server-generated and uses score, correct-answer count, lower total response time, then name ordering.
- Participants receive personal final performance data and a round-wise report.

## 5. Host reporting and archive

- Host sees the current standings and final leaderboard/reports.
- Completed/host-ended quizzes are archived by host account.
- The archive shows the latest five quizzes for that host account.
- An archived quiz can be expanded to inspect its final leaderboard.
- Stored leaderboard JSON includes aggregate and round-wise metrics, even though the current archive UI primarily displays rank, name and score.
- Archives exclude raw question bank content and per-question answer history.
- There is no participant cross-quiz history.

## 6. Operational boundaries

- Local development defaults to memory-only mode.
- Supabase can persist the active competition snapshot.
- The backend supports a single active room and one backend instance.
- The repository contains a manual Socket.IO load simulator. It does not constitute a comprehensive automated test suite or a guarantee about production hosting capacity.

## 7. Not currently promised

Do not claim these are implemented unless the code is changed and tested:
- simultaneous independent rooms;
- horizontally scaled Socket.IO/game state;
- participant cross-quiz history;
- archived question banks or answer-by-answer history;
- a durable per-answer event log;
- multi-region deployment;
- production-grade distributed timer coordination;
- automated browser end-to-end testing;
- automated load testing in the CI pipeline;
- guaranteed support for a particular concurrency level on a free hosting plan.

Keep this list updated when product scope changes.
